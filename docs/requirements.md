# Workforce Hub 要件メモ

## 何を解決するアプリか

シフト、誰がどの案件に何時間使ったか、承認がどこまで進んでいるかを別々の表で管理すると、管理者が全体の稼働状況を追いづらい。Workforce Hub はこの3つをまとめ、チームと案件の稼働を確認できるようにする。

## 利用者

| 利用者 | できること |
| --- | --- |
| メンバー | シフト希望の申請、案件別工数の提出、自分の申請状況の確認 |
| マネージャー | 全メンバーの申請確認、承認・差し戻し、集計ダッシュボードの閲覧 |
| 管理者 | マネージャーと同じ操作を行う想定（将来はユーザー・案件管理を追加） |

## 画面

1. ログイン: メールアドレスとパスワードでログインし、JWT を受け取る。
2. ダッシュボード: 承認済み工数、承認待ち、進行中案件を確認。管理者は案件別の予算時間と実績時間をグラフで比較できる。
3. 工数管理: 作業日、案件、時間、作業内容を提出。管理者は全件を承認・差し戻しできる。
4. シフト管理: 勤務希望日と開始・終了時刻を申請。管理者は承認・差し戻しできる。

## データ設計

- `users` は `roles` を参照し、ロールで権限を区別する。
- `timesheets` はユーザーとプロジェクトを参照し、承認者も記録する。
- `shifts` はユーザーごとの勤務希望・状態・承認者を管理する。
- `approval_logs` は工数申請に対する提出・承認・差し戻し履歴を残す。

## API と権限

認証済みリクエストには `Authorization: Bearer <JWT>` を付与する。メンバーが一覧を取得すると自分のデータだけに絞られ、マネージャー・管理者は全メンバー分を取得できる。承認 API と集計 API はマネージャー以上に限定する。

## 技術構成

- フロントエンド: React / Vite / TypeScript / Recharts
- バックエンド: Node.js / Express / TypeScript / Zod / JWT
- データベース: MySQL 8
- ローカル開発: Docker Compose で MySQL を起動
